*What was chosen, why, and what each choice costs. Every limit here is a limit of this lab.*

## The SIP stack is our own, small, and UDP only

**Chosen:** a minimal SIP user agent in `sipclerk/sip/` (parser, SDP offer and answer, INVITE as server and client, CANCEL, BYE, OPTIONS, INFO, retransmission handling) and an RTP session with G.711 and RFC 4733 digits.

**Why not LiveKit, Asterisk or FreeSWITCH:** the goal was a real INVITE reaching the agent with nothing bought and nothing hosted. A self-hosted LiveKit server plus its SIP service needs Redis, a wide UDP port range and host networking, which Docker Desktop on Windows handles badly, and it would be a platform to configure rather than telephony to show. Asterisk or FreeSWITCH would put a PBX between the caller and the code, so the code would never see an INVITE. The user agent is about 1,150 lines (`message.py`, `rtp.py`, `stack.py`), small enough that every branch can be tested and mutated.

**What it costs:** no TCP, TLS, REGISTER, digest authentication, SRTP, forking, session timers or REFER, and only the transaction behaviour the lab needed. A production line would sit behind a carrier or session border controller (Twilio Elastic SIP Trunking, Telnyx, a LiveKit SIP service) that speaks plain SIP to this process, or this module would be replaced by that platform. None of those was run here.

**Dialogs follow the proxies on their path.** A carrier proxy that record-routes asks to see every later request of the call. The line echoes the INVITE's Record-Route headers in its provisional and 2xx responses unchanged and in order (RFC 3261 12.1.1), keeps them as the dialog's route set, and sends its BYE with a Route header per entry and the peer's Contact as the Request-URI (loose routing, 12.2.1.1; a strict router first takes the Request-URI and the Contact goes last). For a call the line places, the route set is the 2xx's Record-Route read backwards (12.1.2) and the ACK carries it too. A request goes to the first route when that is an IPv4 address and otherwise to where the INVITE came from; a route given as a host name is not resolved, because the lab has no DNS and the nearest hop is the sender in every record-routing deployment tried. The first version dropped Record-Route and sent its BYE straight to a private Contact, so the carrier never saw the hang-up.

**The line waits for the ACK as long as the stack takes one.** RFC 3261 13.3.1.4 has the answering side resend its 2xx, starting at T1 and doubling up to T2, until the ACK arrives, and "if the server retransmits the 2xx response for 64*T1 seconds without receiving an ACK, the dialog is confirmed, but the session SHOULD be terminated", with a BYE. The first version gave up on the call after a fixed 5 seconds while the stack went on resending for 32, so an ACK at 6 seconds (a lost ACK that was resent, a slow carrier) left an answered call with no session, no media and no record, and an ACK that never came dropped the dialog silently. Now `IncomingInvite.wait_for_ack` waits on the stack's own window, the call starts when the ACK comes in time or late, and when it never comes the stack sends the BYE, the line frees its media and stores a record (outcome `dropped_no_ack`, a callback task, both deliveries) so the firm has a trace of a call it answered. `SipStack.t1` is the RFC value 0.5 s and a test shortens it. A caller who is answered and not yet confirmed counts as already on the line, so the longer wait cannot let one number be answered twice, a line that is stopping closes a call that comes out of its ACK wait instead of starting it and waits (up to ten seconds) for its live calls to file their records. **What it costs:** a call that ends in its first moments can leave pipecat tasks that never end (seen only as a test process that hung at the end of its event loop, about one run in several on a loaded machine), which `stop` now waits out and a long running line would carry until restart; that was not reproduced in a deterministic test. **What it costs:** a caller who sends BYE before the ACK is not recorded, an exception after the 200 OK still leaves no record, and answered calls awaiting an ACK do not count against `max_calls`.

**SIPp** (GPL-2.0, from the Debian package, in Docker) is the second, independent SIP caller, so the INVITE is not only ever produced by the code that answers it.

## Pipecat carries the media, the speech models are shared

The pipeline is `RtpInput, Vad, Stt, Intake, Tts, RtpOutput`, all Pipecat frame processors. Pipecat's own Whisper and Kokoro services load a model per instance, which is a cold start on every call, so the services here borrow one `faster-whisper` model and one `kokoro-onnx` model loaded at start. Voice activity detection is Silero, bundled with Pipecat, with `stop_secs` 0.5 so a pause inside a phone number does not end the turn.

Pipecat's streaming resampler was tried first for 8 kHz to 16 kHz and swallowed speech that followed a long stretch of digital silence (found with a 12 second lead of zeros before a clip). `audio.StreamUpsampler` resamples each 20 ms frame together with the tail of the earlier ones and costs 2 ms. A test pins that it matches a whole-signal resample and leaves no click at a frame edge.

Fixed prompts are rendered once, sentence by sentence, and cached: a long line is several cached sentences plus the one sentence that changes ("I have Jordan Reyes."). The numbers report cached and rendered turns separately.

## The model never drives the call

The state machine in `sipclerk/intake/machine.py` decides what happens next. The language model has four fenced jobs, each with a time limit, a validator and a fallback: classify a description into the tenant's practice areas when the keyword reader cannot, read a name or a date the plain parser could not, write one acknowledgement sentence before the closing line, and write the staff summary after the call. An acknowledgement the output guard blocks is dropped, not replaced. With the model down the call completes on plain parsing and the summary falls back to a template (a test and a voice scenario both pin that).

## The guard is keyword rules, on purpose

Before the model: emergencies, existing clients, a request for a person, a request for legal advice, and an unsupported practice area. After the model, before the voice: promised outcomes, legal advice, an implied attorney-client relationship, a commitment nobody made. Rules are named lists of patterns so the mutation check can delete one at a time and a test must notice. A blocked agent line is replaced by a fixed safe sentence.

**What it costs:** a keyword rule misses a rewording it was not written for, and it can fire on an innocent phrase (the word "operator" in a story about a truck operator asks for a person). A classifier would be better at both and cannot be audited line by line. The first version of the emergency rule fired on "I was hurt in a crash", which is most personal injury calls; the test that found it is `test_out_of_scope_is_only_checked_when_asked_and_in_scope_words_win`.

**The emergency rule is about now.** A second round found the same class again: "a truck hit me and I was taken to the emergency room" and "I called 911 at the scene" got the 911 line and a transfer, and the intake was lost. The rule now fires on a danger that is happening now: `call 911` (not `called 911`, not `the 911 call`), `emergency` as an alarm (not `emergency room`, `emergency vehicles`, `emergency contact` and the other places and things), and the condition words (`unconscious`, `bleeding badly`, `not breathing`, `in danger`, `being followed`, `overdose`, `suicide`) unless their clause is an account of the past (`was`, `were`, `had been`, `ago`, `when the paramedics arrived`) with nothing in front of the word that says it is now (`he's unconscious after the fall` still fires). It only ever fires on fewer inputs than before: every new match was an old match. A test pins 30 narrative phrases and 19 live ones, and every condition said with a past subject and a present one. **What it costs:** it is still keywords. A live emergency told in the past tense ("my husband was unconscious and I do not know what to do") is read as an account, a negated phrase ("it is not an emergency") still fires, and spoken digits ("nine one one") are not read.

**An injury or a deadline being reported is not an alarm.** A third round found the class a third time: "my back is hurt" and "my kids are hurt too" are how an injury call goes, and "an emergency hearing", "an emergency protective order" and "it is kind of an emergency" are how a family law or immigration call goes, and each got the 911 line and a transfer (after hours, the intake was cut short). The rule now asks what is being said. A body part that is hurt is never an alarm. A person is an alarm when badly or seriously hurt, or when the caller asks for help right then (`please help`, `right now`, `send an ambulance`, `won't wake up`), and a bare "he is hurt" is a report. `emergency` before a court noun (hearing, motion, order, custody, protective, restraining, stay and the rest of a pinned list) or after a hedge (`kind of`, `sort of`, `a bit of`) is not an alarm, and `in danger of losing my house` and `being threatened with a lawsuit` are legal phrases. Tables pin each phrasing next to the same words said as a real alarm, and a seeded comparison shows the rule fires on strictly fewer inputs than before and on none it did not fire on before. **What it costs:** a caller who says only "my husband is hurt" gets no 911 line (that was the price of not hanging up on "my kids are hurt too", and the intake still goes on); and the class is not closed by keywords. Left alone and logged as known limits: `my brother's suicide last year` (the possessive 's reads as `he's`), `overdosed in March` (a month is not read as the past), `I am being followed by a process server`, `she is dying to know`, `being attacked in the press`, `the emergency procedure was billed twice`, `my mother is unconscious most of the day` and `someone is attacking me` (the last one is a miss, not a false alarm: only `being attacked` is a rule). Each needs a reading of the sentence that keywords do not give, each is rare, and a false 911 line is cleared by the person at the desk.

**A confirmed practice area is not overturned by a word in the description.** The out of scope word check ran on the practice area answer and on the description, so a personal injury caller whose description said the other driver was arrested for DUI was told the firm does not take the matter. The check now runs on the description only while the area is unknown, skipped or one the firm does not list, and still runs on the practice area answer itself. **What it costs:** a caller who confirms an area the firm takes and then describes a different matter is taken, and a person reviews it.

## Names keep their letters

A name is read with the letters of any language, composed to NFC, and an apostrophe, hyphen or period works as it always did, so `Daniel Muñoz` is read back, confirmed, stored and delivered as that. The first parser turned every letter outside A to Z into a space, which stored `Mu Oz` and refused `José García` twice. The ASCII behaviour is pinned against a frozen copy of the old parser on 4,000 seeded random inputs, so widening it changed nothing for an ASCII name. The same sweep covered the other readers of text: the shared normaliser (used for yes and no, dates and practice-area keywords) now keeps letters, so a correction like "no, it is José García" keeps its accents and a firm's keyword written with an accent can match; the word count for a description counts a word in any script; an email stays ASCII on purpose, because it is spelled aloud ("jose dot garcia at example dot com"). **What it costs:** the capitalisation rule is the old one (first letter up, the rest down, `Mc` and `O'` special), so `Jean-Luc` is stored as `Jean-luc`; a name of more than five words is still refused; and speech to text here is English only, so a name in another script is only read if the model produced it. **A filler word is not a veto on a name.** `An Nguyen`, `Thi An Tran`, `Daniel To`, `Kevin Case` and `Mary Hurt` were refused twice and the caller was sent to a person, because `an`, `to`, `case` and `hurt` were on the list of words that are an answer or a filler. Those four (`NAME_AMBIGUOUS`) now count as part of a name when heard capitalised next to a word that is only a name, or when the model already extracted the text as a name (`parse_name(..., named=True)`, so the fallback is no longer rejected by the same check); said alone or in lower case they are still the filler they usually are, and every other word on the list still vetoes. **What it costs:** speech to text that lower-cases a name sends it to the model fallback, and `An Important Question` would be read back as a name (the caller says no).

## Which firm a call is for

The number the caller dialled is read from candidates in a fixed order: the Request-URI (`sip:`, `sips:` or `tel:`), then the To header. Each is reduced to one form (`%2B`, a `00` prefix, visual separators, `phone-context=+1`, eleven digits with no plus and `;npdi` style parameters all become `+` and digits; a trunk name such as `s` or `trunk01` dials nothing) and is accepted only on an exact match of those digits against a firm's number. A national number of ten digits is accepted only when exactly one firm's number ends with it, so a call is never loaded onto a firm that merely looks similar; two firms that share the last ten digits answer only to the full international number. A candidate that matches no firm falls through to the next one; none left is a 404 and nothing is loaded. `P-Called-Party-ID` and `P-Asserted-Identity` are not used: the first is a hint a proxy may add and the second says who is calling. A `tel:` Request-URI is answered like any other (the first version raised inside the handler and the caller heard nothing), and an INVITE the stack cannot parse gets a 400 when the five headers a response copies can be found, so the caller does not retransmit it for half a minute. One caller number holds one call at a time on a firm's line (a second INVITE from it gets 486), but a withheld caller id is nobody in particular: an empty one (`sip:anonymous@anonymous.invalid`), the keypad placeholder `266696687` and a number of only zeros never count as a duplicate, so two anonymous callers are two calls. A retransmitted INVITE with the same Call-ID is answered from the first one's response and never reaches that rule. **What it costs:** a firm whose number is only ever sent as a national number of another length (for example a nine digit number) cannot be matched by that form, and a request that is not an INVITE and cannot be parsed is dropped without an answer.

**Who is calling is read one way.** The caller id was the raw user part of the From header, so a blocked number a carrier sent as ten digits was answered while the `+1` form got 603, and an id with a parameter in the user part (`+14155550142;cpc=ordinary`, `;npdi`, `;rn=`) was stored as an empty number and skipped both the block list and the one call per number rule. `caller_number` now reads a From header, a URI or a block list entry the way a dialled number is read (parameters after the `;` dropped, `sip:`, `sips:` and `tel:`, plus, `00`, `%2B`, visual separators, `phone-context`), and the stored number, the block list and the duplicate rule all use it. `match_number` compares two readings: equal is a match, and a national number of ten digits also matches an international one that ends with it, the other way round too, only when exactly one does, so two countries that share ten digits are never taken for one caller. A withheld id is still nobody in particular. **What it costs:** a ten digit caller is stored without a country code, because nothing in the INVITE says which, and when two blocked numbers share those ten digits neither blocks that caller.

## The clock of a call is the firm's time zone

The tenant file names an IANA zone (`America/Los_Angeles`) and nothing else about the clock: the first version also carried `utc_offset_hours`, typed as -7 and -4, and from the day the clocks go back every weekday the last open hour read as closed ("our office is closed right now" while it was open) and the hour before opening read as open. `Hours.local` converts the instant with `zoneinfo`, the zone is checked when the file loads, a file that still has the offset is refused (unknown keys are forbidden), and the date a call is filed under comes from the same zone. **What it costs:** `tzdata` is a dependency (Windows has no system zone database), and the tenant version and hash changed with the file (2026.10.3 and 2026.10.6).

## The plain readers do not guess what a caller did not say

Third review round, six findings, each fixed as a class with a generated table. **Emails:** a filler or lead-in (`sure`, `yeah`, `um`, `my email is`, `it's`) is dropped from the start, but a lead-in word that a spoken connector follows is the start of the address (`sure at gmail dot com`). **Dates:** a month the caller names decides the date and a relative year only says which year (`March of last year` is March 2025), the day is the number beside the month in digits or words, `the 5th of last month` is the 5th, and `may` is the month only after a preposition, before a day, a year or a number, or as the last word (`it may have been in August` is August). **Keypad:** ten digits that do not start with 1 are a whole number (no US area code starts with 1) and are read back at once; a number that starts with 1 is the eleven digit form. **Existing client:** once the caller has answered no to being a client the rule is not run, because `my case`, `my lawyer is` and `my case manager` then describe the matter. **Keywords:** a keyword is never a function word, so Tidewater lists `a will`, `my will`, `the will`, `his will` and the family possessives, not `will`.

**What it costs, as known limits (the lead scored each 3 or less):** a caller who says no to being a client and later says `I'm already a client` is not handed to a person, since the rule is off for the rest of the call and it takes two faults to meet it; `trust`, `job`, `estate` and `truck` are words with an everyday meaning and still pick an area when they are the only keyword (a tie with another area asks again); a date answer is still taken as heard with no read-back (`October 30th` said on October 26th reads as the future); `No problem` to the recording question turns recording off, which is the safe direction; the staff summary reaches the console record and not the bridge payload, which carries every field with an empty summary; a surname that holds the skip word `pass` skips the email; and an eleventh keypad digit pressed during the read-back is ignored, with a zero going to a person as it does at any moment. Each was run and the code was left as it was because the harm is arguable or needs two faults, and every fix here is a new source of findings.

## A tenant is a file

`tenants/*.yaml`, validated by pydantic models that forbid unknown keys, with a JSON schema exported from the same models. The SHA-256 of the canonical form (sorted keys, no whitespace) and the version are stamped on every record, so a call can be replayed against the exact configuration that handled it. Two firms are loaded at start and two firms with one number is a start-up error. A firm's questions, prompts, transfer destination, hours, recording rule, retention and roles never reach the other firm's call (a test asserts it with two simultaneous calls).

## Warm transfer is a bridged second call

The agent places an INVITE to the tenant's desk phone, speaks a short whisper to staff only, then relays RTP between the two legs, transcoding between PCMU and PCMA when the legs differ. The caller hears a soft ringback while it rings. A busy or unanswered desk phone leaves a callback task and an honest line, never dead air. The desk leg runs as its own task, so the end of the call (the caller's BYE, the desk phone's, a shutdown) cancels it wherever it is: a CANCEL for an INVITE that is still ringing (and an ACK then a BYE for an answer that crosses the CANCEL), a BYE for an answered desk call that is still being whispered to, the whisper and the bridge stopped, the desk leg's media socket and tasks closed, and the callback task still left for the caller. The first version never cancelled the desk INVITE, so a receptionist could answer a call that was already over and hear the whisper while the line kept sending RTP to her phone, and one socket and one task leaked per such call. REFER (handing the caller to the desk phone and leaving) is not implemented.

## Storage, access and the audit line

Every part of a saved call (record, transcript, summary, recording) is AES-256-GCM encrypted under a key derived per tenant, with the tenant, call and part bound in as associated data. Reading goes through `TenantStore.read(actor, ...)`: the actor must belong to the tenant and hold a role the tenant grants for that part, and every read, allowed or denied, writes one hash-chained audit line. A retention setting per tenant deletes expired calls and audits the deletion.

**How retention runs.** `ClerkServer.start()` runs one retention pass at once, so a line that was down for a month does not keep expired calls until the first interval, and then a pass every `retention_every_s` seconds (default 3600). A pass is `TenantStore.purge(now)` with the server's injectable clock, followed by a check of each firm's audit chain (a chain that does not verify is logged at ERROR and shown in `server.retention["audit_broken"]`). A pass that raises is logged with its traceback, counted in `server.retention["failures"]` and tried again at the next interval; it never stops the line. Inside a pass, one call folder that cannot be read (a half written one from a crash, a torn `meta.json`), deleted or audited is skipped, logged and counted in `result.skipped`, and the folders after it and the other firm's are still processed. **What it costs:** a folder with no readable `meta.json` is never deleted by retention, because `meta.json` is written last and a folder without it cannot be told apart from a call still being saved; such a folder needs a person. The master key is a local file in `.secrets/`; a real deployment would use a key management service.

## Delivery never touches the call

A finished intake is queued in an outbox with an idempotency key (tenant, call, intake), sent to two receivers, and retried with backoff on a timeout or a 5xx. A 4xx that will not improve (a bad signature) becomes a dead letter at once.

**Every call that carries a task reaches both receivers by one path.** A caller who hung up mid intake, or while the desk phone rang, got a stored callback task and a console delivery and nothing for the case-management bridge, because that entry was queued only when the machine submitted a record and a hang up never submits. `delivery.queue_call` is now the one place a finished call is queued (the console gets every call, the bridge gets every call that has a task, as `intake.incomplete` when it was never qualified) and `ClerkServer.file_call` stores and queues in one step for every ending: a complete intake, a hang up, a failed transfer, a lost ACK. The bridge entry that is queued while the closing line is still being spoken is the same function with `only="bridge"`, and queueing twice is one delivery. A call that ended in a connected transfer carries no task and goes to the console only. `tests/test_outcome_receivers.py` reads every outcome the machine can assign from its source and fails when one has no case, then checks each stored task against an outbox entry per receiver.

**The retry schedule** (`delivery.BACKOFF_S`) waits 1, 2, 4 ... 2048 seconds, then 1 hour twice, 2 hours twice and 4 hours four times: 21 attempts and 83,295 seconds, about 23 hours, from the first attempt to the last. The first design gave up after 6 attempts and 31 seconds, so a receiver that answered 503 for ten minutes lost the delivery for good without anyone being told. Every attempt carries the same idempotency key and a signature made at that attempt's time. Pending entries and their attempt counts survive a restart. An entry that uses the whole schedule is dead: it is logged at WARNING when it dies, counted in `Outbox.stats()` and `ClerkServer.status()["deliveries"]`, and mentioned in the log by the hourly pass for as long as it stays dead. `python scripts/requeue_dead.py` (`--list` to look first, `--target` and `--key` to pick) gives dead entries a fresh set of attempts: it leaves a request file beside the outbox and the running line applies it on its next pass, because the line rewrites its own copy of the file every pass and an edit made under it would be lost (`--now` edits the file when the line is stopped). A dead entry keeps its encrypted body until its firm's retention, so it can be sent again until then. The outbox is a file, so a restart does not lose a pending delivery. A property test over seeded random failure sequences found a real bug: an empty outbox was written as one blank line and could not be read back after a restart.

**The outbox is the second place caller data rests, so it follows the store's rules.** The body of an entry (name, number, email, the incident text) is AES-256-GCM encrypted under the firm's key with the firm, call and target bound in as associated data, so a body moved to another entry or firm is refused and that one entry goes dead; the file holds no readable caller data in any state. The readable body lives in memory only while an entry waits. Once an entry is delivered its body is dropped and only the id, status and times stay. A dead entry keeps its encrypted body so it can be sent again, and delivered and dead entries are removed at their firm's `retention_days`, counted from when they finished, by the same hourly retention pass that deletes calls. A line of the file that cannot be read is logged and skipped instead of stopping the line from starting. An outbox file written by the first version, with bodies in the clear, is sealed and rewritten when it is read. The same rule covers the logs: no log call in the line interpolates what a caller said or what the agent read back (a test reads every logging call), so an operator who turns on INFO gets lengths and timings, never words. Pipecat's own DEBUG frame log is a separate system that the lab keeps at WARNING; it would show transcripts if someone raised it. **What it costs:** the delivered receivers' own response text (80 characters) stays in the entry's `last` field, which is fine for the two receivers used here and would not be for one that echoes the body.

The two receivers are used the way their repositories document them: `clio-matter-bridge` verifies `x-hook-signature` (HMAC-SHA256 of the raw body) and dedupes on `meta.event`, `data.id` and `data.etag`; `clinic-call-console` takes `POST /api/ingest/calls` with `X-Signature: t=<unix>,v1=<HMAC>`. No Clio account write happens: the stored Clio developer trial token answers 401 (the trial expired in August), so the intake goes to the bridge's own verification code as a Clio-shaped payload.
